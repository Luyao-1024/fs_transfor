## 1. 文档目的与使用方法

本文将项目检视结果转化为可逐项实施、验证和跟踪的开发清单，供后续维护者或开发代理使用。

实施时应先核对对应代码是否已变化，再按问题编号领取任务。每项工作至少记录修改范围、测试结果、未解决限制和完成日期；只有满足验收标准后才能勾选完成。本文中的新增模块名、状态名和接口名均为设计建议，可在保持验收要求的前提下调整。

推荐实施顺序：数据完整性修复 → 连接与任务生命周期 → 任务中心 → 使用效率 → 断点续传与同步。

本文没有承诺排期。应在核心任务模型和后端能力验证完成后估算工期，不宜将所有需求一次性并入一个改动。

## 2. 当前能力与结构

### 2.1 已有用户能力

- 多标签双面板浏览，标签页和路径记忆。
- 本地文件系统和 SSH/SFTP 远端文件系统。
- 同一服务器连接复用，面板级引用计数与断线通知。
- 密钥、密码和 ssh-agent 认证，未知主机指纹确认。
- 面板间拖拽、外部文件拖入、右键传输、内部复制和剪切粘贴。
- 本地复制、上传、下载、跨远端流式复制、同服务器远端 `cp -a`。
- 递归目录传输、覆盖询问、速度进度和取消。
- 新建目录、重命名、本地回收站删除、远端确认后永久删除。

这些能力说明主要工作流已经成形，但不能据此认为异常路径和数据完整性已经得到充分保证。

### 3.2 补充诊断结果

以下复现通过临时目录或模拟后端完成。诊断代码为当次临时执行，尚未加入仓库，因此后续修复需要补成持久回归测试。

| 场景 | 实际观察 | 证据类型 |
|---|---|---|
| 传输层将文件复制到自身并允许覆盖 | 任务显示 `done`，源文件变为 0 字节 | 临时文件复现 |
| 冲突选择跳过，同时配置移动完成回调 | 目标保留旧内容，但源文件被删除 | 临时文件复现；使用与 UI 相同的回调语义 |
| 复制顶层空目录 | 任务显示 `done`，目标目录不存在 | 临时文件复现 |
| 覆盖复制写入一块数据后取消 | 任务显示 `cancelled`，目标留下 524288 字节；后端没有 `remove` 方法 | 临时文件复现 |
| SFTP 文件句柄关闭时抛错 | `_LockedFile.close()` 吞掉异常 | 模拟文件句柄 |
| 删除一个 `stat()` 报告为目录的远端链接 | 递归访问并删除链接下的文件路径 | 模拟 SFTP 调用记录；未操作真实远端 |
| 同服务器远端复制 | 执行 `cp -a`，覆盖询问次数为 0 | 模拟远端命令通道 |

已有测试通过与上述缺陷同时成立：现有测试尚未覆盖这些边界条件。尤其是“启动后立即取消”不能代替“已经写入数据后取消”。

## 4. 优先级和完成定义

| 级别 | 定义 | 处理原则 |
|---|---|---|
| P0 | 可能误删、破坏文件或错误报告写入成功 | 下一轮开发优先完成，作为可靠性版本发布门槛 |
| P1 | 核心行为错误、任务不可管理或生命周期不完整 | 紧随 P0，相关功能扩展前完成 |
| P2 | 使用效率、性能和可维护性改进 | 在正确性基线稳定后推进 |
| P3 | 高级传输和同步能力 | 明确场景并完成依赖后实施 |

单项完成要求：可复现问题已消失，成功/取消/错误路径已验证，UI 和配置影响已记录，相关说明已更新。涉及 UI、连接或传输改动时，按照 [AGENTS.md](../AGENTS.md) 执行核心测试和全部 UI 脚本；应先解决第 8 节所述测试隔离问题。

## 5. 第一阶段：数据完整性与传输正确性

### SAFE-01：修复剪切跳过后误删源文件（P0）

位置：`FilePane._action_paste()`、`_delete_permanently()`、`TransferManager._run()` 和 `_check_conflicts()`。

现状：跳过冲突会从复制列表移除条目，但任务仍正常结束。移动完成回调随后删除原始 `paths` 全部内容。此外，回调在 `enqueue()` 提交线程后才赋值，快速任务存在回调尚未设置就结束的竞态。

实施方案：

1. 将 `copy` / `move` 作为入队时已确定的任务参数，取消 UI 事后附加删除回调的方式。
2. 为每个源条目记录目标、复制结果和提交状态。
3. 只有已成功提交的项目才允许删除源；跳过、失败和取消项目必须保留。
4. 第一阶段对目录移动采用保守规则：只要目录内有跳过或失败，就保留整个源目录，并显示部分完成，避免递归删除未复制内容。
5. 目标已提交但源删除失败时，报告“复制成功，源删除失败”，不得将其当作完全成功或自动重复覆盖。

验收：全部跳过时源完整保留；混合成功和跳过时不误删；空文件和小文件移动无竞态；取消后不删除未提交源；源删除失败可以单独识别。

### SAFE-02：统一源目标身份与路径检查（P0）

位置：`TransferManager.enqueue()`、`_execute()`、`_copy_file()` 和后端路径接口。

现状：部分 UI 入口有同目录判断，但传输层缺少统一保护。两个面板浏览同一路径时，右键传输或跨面板拖拽仍可能进入覆盖自身的流程。

实施方案：

- 在核心层检查同文件、同目录、目录目标位于源内部、重复源和父子源同时选中的情况。
- 本地结合规范路径与文件身份判断，覆盖符号链接和硬链接指向同一文件的情形。
- 远端结合服务器身份与后端规范路径；不能证明文件不同的高风险场景采取保守处理并说明限制。
- 在真正写入或提交前再次检查目标状态，降低预检查后文件变化的风险。
- 所有入口，包括拖拽、剪贴板和重试，使用同一套检查。

验收：同文件复制不会打开目标进行截断；目录复制到自身或子目录在写入前停止；链接别名不绕过保护；错误信息包含具体原因。

### SAFE-03：临时文件写入与安全提交（P0）

位置：`TransferManager._copy_file()`、后端写入和重命名接口。

现状：目标直接以覆盖模式打开，旧文件立即被截断。取消和错误清理调用不存在的 `remove()`，异常又被忽略，导致半成品残留。

实施方案：

1. 在目标文件所在目录生成本任务专属临时文件，使用独占创建避免名称碰撞。
2. 数据写入临时文件，成功关闭并完成必要校验后再替换目标。
3. 由后端明确提供“提交临时文件”和“清理临时文件”的语义，不复用任意递归删除作为模糊清理动作。
4. 本地使用支持的同文件系统原子替换；SFTP 检测 `posix-rename` 等能力。
5. 远端不支持原子覆盖时，第一阶段应安全失败并说明原因；如后续增加备份替换流程，需单独设计恢复规则，不能先删除旧目标再尝试提交。
6. 取消或失败只清理本任务创建的临时文件。清理失败需记录具体路径供用户处理。
7. 两个任务写入同一目标时进行目标级串行协调，提交前重新确认冲突策略。

验收：中途取消、断网、磁盘满、关闭失败时旧目标内容不变；新目标不以正式文件名暴露半成品；临时文件不覆盖已有文件；并发任务不会静默互相覆盖。

限制：文件级原子提交不等同于整个目录事务，也不自动保证断电持久性。目录任务需要显示逐项结果；如需断电保证，应另行定义文件和目录的同步落盘策略。

### SAFE-04：修复远端目录链接删除（P0）

位置：`SftpBackend._delete_rec()` 和 `FileEntry`。

现状：删除使用 `stat()`，会跟随符号链接。链接指向目录时，代码可能递归删除真实目标中的文件，最终删除链接路径又失败。

实施方案：

- 使用 `lstat()` 判断待删对象；符号链接仅删除链接本身。
- 文件模型明确表达普通文件、目录、链接等类型，避免仅用 `is_dir` 承载所有语义。
- 删除与复制的链接策略分别定义。复制在尚不支持保留链接时，应明确报不支持，避免隐式解引用。
- 考虑递归过程中条目被替换成链接的情况；对纯 SFTP 无法提供的抗并发替换保证记录限制，不承诺完全消除远端竞争条件。

验收：文件链接、目录链接、悬空链接和循环链接均不会导致递归删除链接目标；普通目录删除保持正确；权限失败不被错误报告为成功。

### SAFE-05：传播 SFTP 写入完成错误（P0）

位置：`_LockedFile.close()`、`SftpBackend.open_write()` 和任务成功判定。

现状：SFTP 启用管道写入，错误可能延迟至关闭时才返回；当前关闭函数吞掉所有异常。

实施方案：正常完成路径必须传播关闭异常；异常清理路径可尽力关闭，但保留原始错误和清理失败信息。只有目标写入、关闭和提交均成功，任务才能进入已提交状态。

验收：模拟 `write()` 成功而 `close()` 失败时，任务不能显示成功，不能提交临时文件，不能触发移动源删除；源路径、目标路径和失败阶段可查询。

### CORRECT-01：统一远端快速复制与普通复制语义（P1）

位置：`_execute()`、`_remote_fast_copy()`、`exec_cmd()` 和 `du_bytes()`。

现状：快速复制在冲突检查前执行。失败后广泛捕获异常并回退流式复制，无法区分命令不支持和已经部分写入后的失败；关闭 SSH channel 也不能直接视为远端进程已停止。

实施方案：

- 先生成统一执行计划并处理冲突，再选择后端执行方式。
- 明确区分“不支持快速复制”和“执行中失败”；后者保留实际结果，不盲目重跑。
- 快速路径同样满足临时目标、安全提交、链接和元数据策略。
- 取消需验证远端命令停止；无法确认时显示状态未知并说明目标可能仍在变化。
- 在安全语义尚不等价时，允许暂时禁用快速路径，使用已验证的流式复制。
- 进度估计不能将目标已有数据当成本任务完成字节；`du` 估算应标记为估算。

验收：覆盖、跳过、取消在各方向行为一致；命令不可用可安全回退；命令部分失败不会被掩盖；取消不产生虚假的停止承诺。

### CORRECT-02：补齐目录结构和创建错误处理（P1）

位置：`_collect()`、`BaseBackend.walk()` 和 `_execute()`。

现状：目录收集遗漏所选顶层目录。空目录会显示成功但没有输出；只含直接子文件的目录传到 SFTP 时也可能缺少父目录。创建目录的所有 `BackendError` 当前都被忽略。

实施方案：收集包含顶层目录的完整目录树，按父目录优先顺序创建；区分“目录已存在”“同名文件阻挡”“无权限”“连接失败”；扫描支持取消。

验收：顶层空目录、仅含直接文件的目录、多层空目录在本地和模拟 SFTP 上正确重建；无权限或同名文件阻挡时明确失败；扫描取消不继续执行写入。

## 6. 第二阶段：任务与连接生命周期

### LIFE-01：任务持有连接引用（P1）

当前 `ConnectionHub` 主要跟踪面板使用者，`Workspace.close()` 会释放面板引用。最后一个面板关闭时，传输仍可能使用该连接。

需求：面板、排队/运行任务分别持有连接租约；任务结束后在统一清理路径释放。关闭标签只关闭浏览工作区；用户显式断开连接时，需要提示受影响任务并按选择取消。连接死亡事件应同时传播给面板和任务。

验收：关闭最后一个远端标签后，已提交任务可继续；任务结束后无孤儿连接；断线时所有相关任务进入准确状态；剪贴板引用失效连接时可给出可恢复提示。

### LIFE-02：连接请求和浏览请求防止过期回调（P1）

当前浏览已有 token 检查，但旧线程仍可能继续执行；连接请求需进一步审查取消后重发、切换服务器、返回本地和关闭标签的竞争情况。

需求：为每次连接请求分配身份，完成回调只作用于仍有效的请求；共享连接的等待者取消不能误消费新请求。文件操作在打开确认对话框时捕获后端、路径和条目，避免用户切换目录后操作错误位置。

验收：服务器 A 慢连接完成不会覆盖随后选择的服务器 B 或本地面板；关闭标签后不会弹出无归属认证框；重命名、删除确认期间切换位置不会改变目标。

### LIFE-03：统一退出与取消（P1）

当前窗口关闭只保存会话，传输线程池、等待对话框和周期定时器缺少统一退出协议。

需求：标题栏关闭和菜单退出走同一条路径。存在任务时提供等待完成、取消并退出、返回应用的选择；排队任务可立即取消；运行任务和扫描可协作取消；退出释放对话框等待、任务、连接、监听器和 GLib 定时器。

验收：没有任务时正常快速退出；任务中退出不会留下损坏的正式目标文件；无后台进程长时间等待无人响应的对话框；网络操作有合理超时。

### TASK-01：完整任务中心（P1）

现状：通知最多展示 5 条，超出后隐藏旧通知；成功记录 3 秒后从管理器移除。通知视图不足以管理批量传输。

需求：

- 保留轻量通知，增加可随时打开的完整任务列表，通知关闭与任务记录删除分离。
- 区分排队、扫描、等待确认、传输、提交、完成、部分完成、取消、失败。
- 展示源、目标、文件数、已完成字节、跳过项和失败原因；总量未知时不显示误导性的百分比。
- 支持排队取消、单项重试、仅重试失败项、批量清理已结束记录。
- 任务历史按数量或天数保留，不保存密码或密钥口令；应用重启不自动重放移动或删除。
- “暂停”和“断点续传”不在本阶段默认承诺，避免将重新开始伪装成恢复。

验收：超过 5 个任务仍全部可查和可操作；错误不会随通知消失；重试会重新校验源和冲突；任务结果能够解释部分成功。

## 7. 核心设计与工程优化

### 7.1 建议的传输模型

先让核心层产生结构化结果，再由 UI 展示。可逐步引入以下概念，不要求一次性创建全部模块：

| 概念 | 建议内容 |
|---|---|
| 任务请求 | 源/目标后端、源路径、目标目录、复制或移动、冲突策略 |
| 执行计划 | 目录顺序、文件/链接类型、目标映射、冲突与预估大小 |
| 逐项结果 | 已提交、跳过、复制失败、源删除失败、取消，以及错误阶段 |
| 汇总结果 | 完成项数、跳过项数、失败项数、总字节、是否部分完成 |
| 后端能力 | 原子覆盖、链接操作、远端命令、恢复读写、元数据保留能力 |

关键约束：只有已提交的目标才计入可删除源的集合；任务状态转换由核心层负责；GTK 更新仍通过 GLib/GTK 事件路径；UI 使用一致的状态快照。

### 7.2 UI 职责拆分（P2）

`pane.py` 在检视时为 964 行。优先提取文件操作服务、拖拽/剪贴板到任务请求的转换、连接控制逻辑。面板保留列表展示、选区、菜单与交互绑定。

采用小步提取：每次仅迁移一种职责并运行相关回归，不在可靠性修复中同时进行大范围 UI 重写。

### 7.3 大目录与慢网络性能（P2）

先测量，再调整并发或块大小。基准应覆盖 1 千、1 万、10 万条目录项，小文件集合，大文件，以及可控的高延迟后端。

记录首屏出现时间、完整加载时间、UI 可交互性、内存峰值、吞吐和取消延迟。当前没有这些实测基线，因此本文不宣称任何吞吐提升幅度。

候选方案：有界线程池、合并重复刷新、取消过期扫描、分批插入列表、迭代式遍历；复用 SSH transport 但为浏览和传输分配受控的独立 SFTP channel。不能简单移除共享 SFTPClient 的锁。

刷新时保持选区和滚动位置；传输结束按后端身份与路径共同匹配刷新目标，移动还要刷新源，避免仅凭相同路径字符串刷新无关服务器。

### 7.4 配置、日志与 SSH 体验（P2；相关安全缺陷提前处理）

- 校验配置字段类型、端口范围、标签结构和活动索引；保留旧格式迁移测试。
- 配置损坏时可恢复默认值，但保留诊断信息；保存失败给出非阻塞提示。
- 配置写入合并和串行化，保持原子替换；日志不包含密码、口令或私钥内容。
- 日志包含任务 ID、失败阶段、异常类型和必要路径；路径本身可能敏感，应支持用户控制导出。
- 当前 `known_hosts` 仅在文件已存在时保存新接受的密钥，应补齐首次创建与保存失败提示。
- 使用便于与 OpenSSH 对照的 SHA256 指纹，明确区分未知主机与主机密钥变化；不得自动接受变化的密钥。
- 补充 SSH 配置支持范围说明；当前导入并不等同于完整支持 ProxyJump、ProxyCommand 等选项。
- 新建目录与重命名校验单个名称，阻止意外路径穿越；重命名覆盖应有明确策略。
- 明确时间戳、权限、可执行位和链接保留规则，消除 `cp -a` 与流式复制间未说明的差异。

| 测试组 | 必须覆盖的场景 | 主要断言 |
|---|---|---|

| 移动 | 全部跳过、混合结果、部分目录失败、源删除失败 | 仅允许删除已成功提交的源 |

| 配置与历史 | 格式损坏、旧版迁移、写入失败、重启 | 可恢复、不丢凭据边界、不重放破坏性操作 |

模拟后端应支持在指定字节数或指定阶段注入失败，并能够模拟“不自动创建父目录”的 SFTP 行为。以同步点控制取消时机，避免仅靠 `sleep()` 撞竞态。判断内容一致应比较内容或摘要，不能只比文件大小。

## 9. 后续功能需求与边界

### UX-01：导航和选择效率（P2）

需求：前进/后退、目录收藏、最近路径、当前目录快速筛选、常用导航快捷键。收藏记录服务器标识与路径，不记录密码。

验收：每个面板独立维护导航历史；筛选不会改变真实目录；隐藏的旧选区不会参与误操作；收藏失效时提示并允许编辑或移除。

### UX-02：系统剪贴板互通（P2）

需求：与常见 Linux 文件管理器交换本地文件复制信息。远端文件没有直接可用的本地 URI，需要明确限制或显式下载流程。

验收：本地文件可跨应用复制；外部剪切协议未完整支持前不伪装成已完成移动；不能将远端路径当成本地路径读取。

### SSH-01：跳板机与连接配置完善（P2）

需求：根据实际使用场景增加 ProxyJump、连接超时等选项；扩展连接池身份，使不同路由或关键连接参数不会错误共享连接。

验收：跳板认证与目标认证可区分；配置重启后可恢复；错误清楚指向失败节点；主机密钥验证覆盖每一跳。ProxyCommand 涉及命令执行，需单独定义可信配置来源与处理方式。

### ADV-01：断点续传（P3）

前置：安全临时文件、任务历史、随机位置读写、明确的源文件身份与变化检测。

需求：保留可识别的临时数据和恢复元信息；恢复前检查源是否变化、目标临时文件是否属于该任务以及已写数据是否匹配。大小和时间戳不能单独证明内容相同。

验收：中断后可正确恢复；源发生变化时停止恢复并说明原因；过期任务不会覆盖无关文件；恢复不自动删除源。先支持单文件，再扩展目录。

### ADV-02：目录对比与单向增量同步（P3）

前置：链接和元数据规则、冲突策略、逐项结果、安全提交。

需求：先生成只读差异预览，展示新增、更新、冲突和可能删除项；首版单向同步默认不删除目标额外文件。明确时钟偏差、时间精度、大小比较和内容校验的差别。

验收：用户执行前能审阅计划；计划过期需重新校验；首次使用不包含默认镜像删除；失败后可定位和重试单项。双向同步、自动删除和定时执行留待独立需求设计。
